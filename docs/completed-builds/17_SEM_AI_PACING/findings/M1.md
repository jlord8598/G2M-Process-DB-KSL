**Unpivot rule:** each source table unpivots a declared column list, `INCLUDE NULLS`, with k stated per table. The count identity is `count(XFRM rows of table) x k = count(SEM_AI_PACING rows of table)`. Proposal: the declared list is the columns the table populates today (k in `sources.md`, 8,452,970 rows); always-null columns are left out (Q-01).

### Does not fit cleanly
- **NEWBURY OPS_RATE_SHOPS** (38,848 rows) is competitor rate shopping, not pace: its sites are 8 competitor hotels, and its only metric is an offered rate. 989 cells have several rows in one file (597 with different rates), so only SOURCE_LINE_KEY identifies a row (Q-03).
- **KSL / PEREGRINE EVENTS** (509,463 rows) have no occupancy date; EVENT_DATE is used, with STAY_GRAIN EVENT_DAY (Q-04).
- **BEAUMIER** has no snapshot series (Q-02).
- **NEWBURY DATA_TYPE** OTB-7..OTB7 is a vantage relative to the report date, not a date. It is carried in VANTAGE, and SNAPSHOT_DATE stays the report date.
- **UNDER_CANVAS COLUMN10** is a text column of unclear meaning, carried as an attribute only if the owner wants it (Q-05).
- **KSL / PEREGRINE pace rows are booking-level**, including Lost Business / Turned Down / Prospect. BOOKING_STATUS is required, or a sum mixes lost and definite business.

## 3. Snapshots are never summed across
**IS_LATEST_SNAPSHOT = SNAPSHOT_DATE = max(SNAPSHOT_DATE) per SOURCE_LANE, SITE, SOURCE_TABLE.**
- **Per site, not per table,** because a site can be missing from the newest file and its latest view is then older (measured: KSL ROOMS sites per snapshot vary 37-41).
- **Files split by stay year** (ALTERRA, THE_PIG, UNDER_CANVAS WEEKLY: 2 files, the same snapshot date, 0 site-snapshots in both) or by currency (BEAUMIER) share a snapshot date, so both halves are latest together. 0 duplicate cells within a snapshot in all of these.
- **NEWBURY:** the flag is computed per table; DATA_TYPE is a vantage within the snapshot, not a second snapshot.
- **Rule for consumers (section 4 text):** any SUM over SEM_AI_PACING filters to one SNAPSHOT_DATE or IS_LATEST_SNAPSHOT, one VANTAGE, IS_ADDITIVE, and one CURRENCY_CODE.

## 4. Non-additive measures
IS_ADDITIVE FALSE, with the unit:
- OUTRIGGER *_OCCUPANCY (RATIO, 0..1.33), *_ADR (RATE);
- KSL / PEREGRINE AVG_RATE (RATE; AMT = AVG_RATE x QTY on every row, 0 mismatches);
- NEWBURY RATE_VALUE (RATE);
- THE_PIG TODAY_VS_*_CHANGE (PERCENT_CHANGE, -1..45).

THE_PIG *_DIFF are additive differences (DIFF = TODAY - STLY, 0 mismatches on 5,184 rows).

**BEAUMIER OCCUPANCY** (0..772) is not a ratio by its values: it reads as room nights. Its unit needs the owner (Q-02). Pickup columns are additive within one snapshot only.

## 5. Reconcile plan
- **Per lane, source table, METRIC_NAME and SNAPSHOT_DATE:** `sum(XFRM column) = sum(VALUE)` and `count_if(XFRM column is not null) = count_if(VALUE is not null)`, tolerance 0.005.
- **Plus the row identity:** `XFRM rows x k = SEM_AI_PACING rows` per table.
- **Script:** `scripts/reconcile_PACING.sql`, one statement per lane, ending with TOTAL FAILURES.
- **Check 5:** HASH_AGG run A = run B.
- **Check 2:** per (lane, site, source table) exactly one latest SNAPSHOT_DATE; no IS_ADDITIVE FALSE metric with a CURRENCY_CODE unless its unit is RATE; CURRENCY_CODE null iff METRIC_UNIT is not CURRENCY or RATE.
