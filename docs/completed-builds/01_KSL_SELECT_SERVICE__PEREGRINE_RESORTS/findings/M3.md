the shared one is `SPROC_STG_SHARED_CHART_OF_ACCOUNTS` building

**MAINs.** `SPROC_STG_{LANE}_MAIN` now calls the shared chart model and the
lane's 12 models (`models=13`), passing its own `RUN_ID`. The shared model is
called by both MAINs and rebuilds identically: its hash is the same in both
runs.

**`DEV_G2M_AI` now holds exactly 25 base tables, all in `STAGING`.** There
are no other tables, views or temporary objects (`INFORMATION_SCHEMA.TABLES`).

### Design points

- **Raw columns are carried verbatim.** Standard columns are derived
  alongside them and never in place. Mappings are in `docs/sources.md`,
  "Staging rules".
- **`DEPARTMENT_NAME`** comes from a chart lookup that reads
  `CLN.CLEAN.CUR_PROFITSWORD_CHART_OF_ACCOUNTS` and is grouped to one row
  per (tenant, department code) with `min(department)`. That grouping is a
  dictionary dedupe on the join (CLAUDE.md section 8, trap "a source
  dictionary may not be unique"), not an aggregation of fact rows. It reads
  `CLN.CLEAN` directly, the same as every staging model, so no staging
  model depends on another.
- **Pacing and dictionaries** keep their source shape: `src.*` plus
  `RUN_ID`, `SOURCE_LANE` and `SOURCE_TABLE`.
- **No `WHERE` clause excludes a row.** Every model has `where 1=1` only.
