## How `run_build.sql` reports progress

The harness is an anonymous block. It calls the seven MAINs in sequence
(STG, XREF, XFRM, SEM; KSL_SELECT_SERVICE before PEREGRINE_RESORTS in each
layer) with `CALL ... INTO`.

**Measured:** a CALL made inside an anonymous block does not appear in
`QUERY_HISTORY_BY_SESSION`. Only the outer `execute immediate` does. So the
harness records progress in two session variables:
- `RUN_BUILD_STARTED`, set before each MAIN;
- `RUN_BUILD_COMPLETED`, appended after each MAIN.

A probe showed these survive a failed block. They are set with
`execute immediate 'set ...'`, so nothing is caught and no object is
created.
