## 1. DAILY_LABOR
Full table: `docs/sources.md`.
- **Rows today:** KSL 787,419 and PEREGRINE 354,052, all in SEM_AI_UNKNOWN as UNCLASSIFIED_ACCOUNT, H1 null.
- **Measures:**
  - wages: AMOUNTS (= SOURCE_AMOUNT), USD;
  - hours: HOURS (= STAT_VALUE);
  - EFFECTIVE_RATE (AMOUNTS / HOURS, a rate).
- **No FTE or headcount measure.**
- **Grain:** one row per site x business date x person x LABEL x LABOR_TYPE.
- **Dimensions:** department (the LABEL's number) and position (in LABEL). Labor type: KSL 56, PEREGRINE 37 values (Regular, Overtime, PTO, tips, service charge, contract, ...).

## 2. Line key and classification

  - LABOR_TYPE is needed: 97 KSL labels span several types.
  - The null-safe form is needed: LABOR_TYPE is null on 5,932 KSL rows.
  - **It embeds PERSON_ID, an employee identifier (Q-03).**
- **Keys:** KSL 6,213 and PEREGRINE 3,832 labor keys. All are Unclassified, and **none is shared with a non-labor row**, so a D-44 re-seed touches only labor.
- **Conflict (Q-01).** Each row carries wages and hours, but METRIC_UNIT is per key (D-19, check 2(d)): one key cannot be both CURRENCY and HOURS.

| | (A) one row per line (recommended) | (B) two rows per line |

| Classification | the 10,045 existing keys re-seeded (D-44): H1 Statistic, METRIC_UNIT CURRENCY, VALUE_SIGN null (B09-D4) | wage keys re-seeded, plus **10,045 new STATISTIC keys** with METRIC_UNIT HOURS |

**Proposed mapping** (either shape):
- H1 Statistic.
- H2 'DAILY_LABOR', the source's own name (D-38). LABOR_TYPE varies within a key, so it cannot be the family.
- H3-H5 UNCLASSIFIED; P_L_SECTION, NORMAL_BALANCE and VALUE_SIGN null.
- METRIC_UNIT CURRENCY for wages.
- AGGREGATION_TYPE UNRATIFIED: the source states none (D-30). FLOW only if you say so (Q-04).

**Rates:** EFFECTIVE_RATE is a rate and is not carried to semantic (only SOURCE_AMOUNT and STAT_VALUE are). Wages and hours are additive.
